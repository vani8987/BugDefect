# Идеи для развития BugDefect

Этот файл хранит будущие идеи по проекту. Сюда можно складывать всё, что пока не обязательно делать сразу, но важно не потерять.

## Этап 1: стабилизация перед MVP и деплоем

Завершено.

## Этап 2: развитие дефектов

Функции, которые сделают дефекты полноценными задачами внутри доски.

### CRUD дефектов

- Обновление названия, описания, статуса и исполнителя дефекта.
- Удаление дефекта.
- Подтверждение удаления дефекта через модальное окно.
- Отдельная загрузка состояния при обновлении и удалении дефекта.
- Валидация на frontend для формы обновления дефекта.

### Уведомления по дефектам

- Создание уведомления исполнителю при назначении нового дефекта.
- Создание уведомления исполнителю при смене исполнителя дефекта.
- Переход из уведомления сразу на доску или страницу дефекта.
- Отдельный тип уведомления `defect_assigned`.

### Порядок и drag-and-drop

- Перемещение дефектов внутри одного статуса с изменением порядка.
- Сохранение полного порядка дефектов внутри статуса.
- Общий frontend helper для перестановки элементов массива и пересчёта `position`.
- Backend-метод для массового обновления позиций дефектов.

### Дополнительные поля

- Приоритет дефекта.
- Дедлайн дефекта.
- Метки или тип дефекта.
- Фильтрация по исполнителю, статусу и приоритету.
- Поиск дефектов по названию и описанию.

## Этап 3: управление досками и участниками

Функции для командной работы и управления доступом.

### Доски и участники

- Обновление названия и описания доски.
- Управление ролями участников внутри доски.
- Передача владельца доски другому участнику.
- Поиск и фильтрация участников.
- Страница настроек доски.
- Отдельная история приглашений на странице доски.

### Права доступа

- Более точные права для ролей `admin`, `developer`, `guest`.
- Запрет изменения системных данных гостем.
- Единый список доступных действий на frontend по роли пользователя.
- Дополнительные middleware/helper-методы для нестандартных прав доступа.

## Этап 4: авторизация и безопасность

Функции, которые улучшают безопасность аккаунтов.

### Восстановление пароля

- Восстановление пароля через email.
- Таблица `password_reset_tokens`.
- Ограничение частоты запросов на восстановление.
- Срок жизни токена, например 15-30 минут.
- Страницы frontend: запрос восстановления и установка нового пароля.

### Подтверждение контактов

- Подтверждение email через одноразовый код.
- Подтверждение телефона через SMS-код.
- Хранение кодов подтверждения с ограниченным сроком жизни.
- Ограничение частоты отправки кодов.
- Повторная отправка кода с таймером на frontend.

## Этап 5: страница дефекта

Отдельная страница нужна после базового CRUD дефектов.

### Страница задачи

- Отдельный маршрут `/boards/:boardId/defects/:defectId`.
- Просмотр полной информации о дефекте.
- Редактирование дефекта со страницы.
- Комментарии к дефекту.
- История изменений дефекта.
- Вложения файлов к дефекту.
- Отображение автора, исполнителя и дат изменения.
- Привязка дефекта к git-ветке.
- Генерация имени ветки по `DEF-{id}` и названию дефекта.
- Ссылка на ветку из карточки или страницы дефекта.

### GitHub-интеграция

- Настройки репозитория для доски или проекта.
- Создание GitHub-ветки из BugDefect по выбранному дефекту.
- Хранение `branch_name` у дефекта.
- Хранение ссылки на pull request.
- Получение статуса pull request через GitHub API.
- Защищённое хранение GitHub token только на backend.
- Автоматическое изменение статуса дефекта после merge.

## Этап 6: качество и архитектура

Технические улучшения, которые стоит делать по мере роста проекта.

### Backend

- Дальше выносить повторяющиеся проверки из контроллеров в middleware/helper-слой.
- Добавить общие helper-функции для валидации положительных ID и body-полей.
- Сделать единый формат ошибок API.
- Добавить транзакции для сложных действий, например принятия приглашения.
- Добавить пагинацию уведомлений, досок и дефектов.
- Добавить больше точечных проверок прав доступа.
- Добавить методы моделей для частых запросов вместо ручных циклов в контроллерах.
- Проверить сохранение авторизации после перезапуска backend-контейнера.

### Frontend

- Общие helpers/stores для обработки ошибок API, сообщений и loading-состояний.
- Skeleton-loader для списков и карточек.
- Toast-уведомления для успешных действий и ошибок.
- Empty states для всех пустых разделов.
- Вернуть временно скрытые статистические карточки задач после появления корректных счётчиков.
- Настроить счётчики задач на главной странице и странице доски.
- Страница `/download` со ссылками на будущие приложения и расширения.
- Страница `/api` с документацией API-эндпоинтов и примерами запросов.
- Адаптивная версия меню уведомлений.
- Улучшенная мобильная адаптация рабочих страниц.
- Тёмная и светлая тема.

### Проверки и документация

- Backend-тесты для авторизации, досок, приглашений, статусов и дефектов.
- Frontend type-check в CI.
- CI/CD pipeline для автоматической проверки и деплоя.
- Автоматический запуск `npm run type-check`, `npm run build` и PHP syntax-check в CI.
- Автоматический деплой на сервер после merge в стабильную ветку.
- Отдельные переменные окружения и секреты для CI/CD.
- Docker-команда для полного сброса базы и миграций.
- Документация API с примерами запросов.
- OpenAPI/Swagger документация для backend API.
- Swagger UI страница для чтения и тестирования API-запросов.
- Описание auth, boards, statuses, defects и notifications endpoints в OpenAPI.
- Seed-данные для локальной разработки.
