# Идеи для развития BugDefect

Этот файл хранит будущие идеи по проекту. Сюда можно складывать всё, что пока не обязательно делать сразу, но хочется не потерять.

## Этап 1: базовый продукт

То, что нужно довести в первую очередь, чтобы приложение работало как цельная система.

### Уведомления и приглашения

- Принятие и отказ от приглашения прямо из меню уведомлений.
- Статусы приглашений: `pending`, `accepted`, `declined`.
- Добавление пользователя в доску после принятия приглашения.
- Автоматическое скрытие обработанных приглашений из активных уведомлений.
- Уведомления для владельца доски о принятии или отказе пользователя.

### Задачи и дефекты

- CRUD для дефектов внутри доски.
- Колонки по статусам: новые, в работе, проверка, готово.
- Возможность добавления своих колонок.
- Drag and drop дефектов между статусами.
- Приоритеты, исполнители и дедлайны.
- Комментарии и история изменений дефекта.


## Этап 2: управление досками и безопасность

Функции, которые делают продукт удобнее для командной работы и безопаснее для пользователей.

### Доски и участники

- Управление ролями участников внутри доски.
- Удаление участника из доски администратором.
- Передача владельца доски другому участнику.
- Поиск и фильтрация участников.
- Страница настроек доски.
- Отдельная история приглашений на странице доски.

### Авторизация и безопасность

- Восстановление пароля через email.
- Таблица `password_reset_tokens`.
- Ограничение частоты запросов на восстановление.
- Срок жизни токена, например 15-30 минут.
- Отдельные страницы frontend: запрос восстановления и установка нового пароля.
- Подтверждение email через одноразовый код.
- Подтверждение телефона через SMS-код.
- Хранение кодов подтверждения с ограниченным сроком жизни.
- Ограничение частоты отправки кодов.
- Повторная отправка кода с таймером на frontend.

### Интерфейс

- Тёмная и светлая тема.
- Более подробные состояния загрузки для страниц и модальных окон.
- Улучшенная мобильная адаптация рабочих страниц.

## Этап 3: архитектура, качество и фоновые задачи

Технические улучшения, которые стоит делать, когда функциональности станет больше.

### Backend и архитектура

- Транзакции для сложных действий, например принятия приглашения.
- Методы моделей для частых запросов вместо ручных циклов в контроллерах.
- Единый формат ошибок API.
- Пагинация уведомлений, досок и дефектов.
- Больше точечных проверок прав доступа.
- Worker-сервис для фоновых задач: email, SMS, очистка старых уведомлений и отчёты.

### Качество

- Backend-тесты для авторизации, досок, приглашений и уведомлений.
- Frontend type-check в CI.
- Docker-команда для полного сброса базы и миграций.
- Документация API с примерами запросов.
- Seed-данные для локальной разработки.

### Интерфейс

- Skeleton-loader для списков и карточек.
- Toast-уведомления для успешных действий и ошибок.
- Empty states для всех пустых разделов.
- Адаптивная версия меню уведомлений.

### Возможные отдельные сервисы

- Python-сервис для подтверждения email через одноразовый код.
- Python-сервис для подтверждения телефона через SMS-код.
- Python-сервис для аналитики дефектов и отчётов.
- Python-сервис для автоматической классификации дефектов.

## Этап 4: отдельные клиенты и экосистема

Большие идеи на будущее, если проект вырастет за пределы одного web-приложения.

### Будущие клиенты

- Отдельное мобильное приложение для работы с досками и уведомлениями.
- Desktop-приложение для быстрого доступа к проектам.
- Браузерное расширение для быстрого создания дефекта с текущей страницы.
- vs code расширение для быстрого создания дефекта с IDE.
- Авторизация клиентов через общий API.
- Push-уведомления для приложения и расширения.
